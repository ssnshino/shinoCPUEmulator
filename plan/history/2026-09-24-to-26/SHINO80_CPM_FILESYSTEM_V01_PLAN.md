# SHINO-80 CP/M Filesystem & Starter Disk v0.1 PLAN

Date: 2026-09-26

## Goal

Turn the bootable but empty CP/M 2.2 A: medium into a real, writable starter
disk. The image must be generated deterministically from original SHINO files,
boot through the existing MON `O` / CBIOS path, and remain a standalone HTML
runtime with no network dependency.

## Sources and decisions

- Digital Research CP/M 2.2 defines 32-byte directory entries, 128-byte
  records, logical extents and DPB-driven allocation.
- The existing SHINO DPB is the standard 77 x 26 x 128-byte layout with
  1,024-byte blocks, 64 directory entries, two reserved directory blocks and
  two reserved system tracks.
- No historical transient-command binary is imported in this phase. All
  bundled user files are original SHINO material, avoiding an additional
  third-party license gate.

Reference:

- `https://ftpmirror.infania.net/sites/www.gaby.de/cpm/manuals/archive/cpm22htm/ch6.htm`
- `https://manpages.debian.org/testing/cpmtools/cpm.5.en.html`

## Scope

- Add a deterministic CP/M 2.2 filesystem packer for the current DPB.
- Populate A: with:
  - `WELCOME.TXT` — usage and provenance text readable by CCP `TYPE`
  - `HELLO.COM` — original SHINO BDOS console demonstration
  - `S80INFO.COM` — original SHINO machine/CP/M identity utility
- Preserve E5h in every unused directory entry and unused medium byte.
- Keep system tracks, CCP, BDOS and CBIOS byte-identical to the parent.
- Test real Z80/BDOS/CBIOS reads and writes, including a CCP-created file that
  survives WBOOT.
- Update the standalone artifact, Technical Manual, current snapshots and a
  matching worklog.

## Non-goals

- No CPU, decoder, flags, CBIOS ABI, BDOS or CCP semantic changes.
- No imported `PIP`, `STAT`, `ED`, `ASM`, `DDT`, `LOAD` or BASIC binary.
- No host file picker, download/export, LocalStorage/IndexedDB persistence or
  second disk drive.
- No mechanical FDC timing, skew simulation or physical image interchange.
- No automatic merge or public deployment.

## Accuracy and invariants

- Directory entries are 32 bytes and use user 0, uppercase 8.3 names, extent
  numbers, 128-byte record counts and one-byte allocation pointers because
  `DSM=242`.
- Blocks 0 and 1 remain reserved for the 64-entry directory (`AL0=C0h`).
- File data starts at block 2 relative to logical track 0 after `OFF=2`.
- Files may span multiple 16 KiB extents; each block is owned by exactly one
  file extent.
- File bytes are record-padded with CP/M text EOF `1Ah` unless the caller
  explicitly supplies another padding byte.

## Risks

- A directory/block offset error could make BDOS overwrite the system tracks.
- Incorrect `EX`/`S2`/`RC` fields could list a file but truncate or misread it.
- Tests that only parse the generated bytes could repeat the same bug; runtime
  tests must execute CCP/BDOS through the actual CPU and block-device ports.
- `SAVE` modifies the mounted image and must be tested on a fresh per-test copy.

## Verification

- Unit-test filename validation, exact directory entries, block ownership,
  multi-extent packing, deterministic output and bounds failures.
- Assert system-track CCP/BDOS/CBIOS bytes remain unchanged.
- Boot via MON `O`, then execute `DIR`, `TYPE WELCOME.TXT`, `HELLO` and
  `S80INFO` through the keyboard and CCP.
- Execute CCP `SAVE` to create a new file, verify its directory/data sectors,
  WBOOT through address 0000h and prove the new file remains visible.
- Run the full package suite, deterministic one-page/manual builds, diff check
  and installed-browser desktop/mobile smoke.

## Success conditions

- `DIR` lists all three starter files instead of `NO FILE`.
- Text and both COM files execute correctly under the resident CP/M 2.2.
- CP/M creates a file through CBIOS WRITE and it survives warm boot.
- The distributed one-page HTML remains self-contained and deterministic.
- The branch is delivered as one logical commit and a stacked PR on cursor /
  beeper PR #36, without merging it automatically.

## Human QA remediation — iPhone 2026-09-26

Human testing on iPhone Edge confirmed `DIR`, `TYPE WELCOME.TXT`, `HELLO` and
`S80INFO`, then found two CBIOS console defects exposed by interactive CP/M:

- Backspace reached the guest as 08h, but RAM CBIOS CONOUT rendered it as a
  printable control glyph instead of moving the cursor left. The result looked
  like tab spacing while editing a CCP command.
- Reaching the bottom of DM-80 wrapped the CBIOS cursor to C000h instead of
  scrolling 24 rows upward and clearing the last row.

Remediation scope is deliberately limited to RAM CBIOS console semantics and
matching tests/docs/artifacts. Preserve the already-correct iOS
`beforeinput=deleteContentBackward` to 08h mapping, CP/M filesystem content,
CPU semantics, ROM BIOS behavior and display renderer. Verify direct CBIOS
BS/scroll behavior plus a real CCP line edit containing Backspace, rebuild both
standalone artifacts, rerun the full package suite and mobile/desktop Chrome.
